## Automatické overenie

Použitý .NET SDK: **10.0.401**. Finálny príkaz z koreňa repozitára:

```powershell
.\scripts\Test.ps1 -NoRestore -BuildAndroid -BuildWindows
```

Testy používajú skutočný zdroj služieb a ViewModelu. Preferences/SecureStorage,
biometria a MQTT klient sú riadené náhrady. Samostatná TLS skúška používa
skutočný MQTTnet transport a loopback server s nedôveryhodným certifikátom;
overila odmietnutie certifikátu. Živý cloudový broker sa nepoužil.

## Nové overené scenáre

- Profily zachovajú ID pri úprave a prejdú JSON round trip. Katalóg odmieta
  duplicity, neznáme funkcie/verziu a viac než 32 zariadení.
- Teplotný profil nevyžaduje otváranie; otváranie vždy vyžaduje stav polohy.
- Verejný katalóg neobsahuje heslá, HMAC ani MQTT používateľa. Každé ID má
  vlastné secure údaje; ani prehodené bundle nemožno použiť medzi profilmi.
- Zmena hosta/témy/funkcií/ID iba vo verejných metadátach nesprístupní credentials.
- Zlyhaný secure zápis zachová pôvodné údaje. Čiastočný zápis metadát zablokuje
  nezhodný profil; konzistenciu obnoví opätovné uloženie správnych údajov.
- Staré nastavenia sa zobrazia bez čítania tajomstiev. Autorizované načítanie
  migruje údaje; prerušenie migrácie zachová pôvodné kľúče a umožní opakovanie.
- Odstránenie jedného profilu zachová credentials druhého. Neplatný alebo
  novší katalóg sa neprepíše prázdnym.
- MQTT služba odmietne priamy príkaz read-only profilu aj pri čerstvom `closed`.
- Prepínanie A → B → A zachová watermark a vyradené relácie. Správy starej
  inštancie klienta aj nesprávnej témy sa ignorujú.
- Zmena brokera/portu/režimu nevymaže replay históriu podpísaného toku;
  návrat k pôvodnému HMAC kľúču zachová jeho watermark.
- Limit 64 MQTT identít zablokuje novú identitu a zachová existujúcu ochranu.
- Načítanie iného profilu najprv odpojí pôvodný a vyžaduje nové prihlásenie.
  Nový koncept nepreberá staré credentials ani endpoint.
- Rozpracovaná biometria blokuje iné príkazy; zmena výberu/konfigurácie počas
  nej zabráni odoslaniu. Prechod do pozadia pri prepínaní neobnoví prihlásenie.
- Vymazanie nullable vstupného poľa nespôsobí pád; neplatné nastavenie sa neuloží.

Lokálne ID ešte nie je súčasťou podpísaného wire formátu. Funkcie sa zatiaľ
konfigurujú používateľom; nie sú výsledkom vyjednávania s firmvérom. Aj profil
iba na meranie vyžaduje existujúci MQTT formát vrátane `door`. Starý formát
credentials neobsahoval secure kópiu metadát; pred prvou migráciou sa overuje
pôvodný endpoint. Ďalší krok A3 musí zachovať kompatibilitu existujúcich dosiek.
